# Component authoring conventions

Every component is one GLB generated by a *family function* in
`blender/starship/components/<module>.py` using the helpers in `starship/kit.py`.

```python
from ..kit import family

@family("console", ["helm", "ops", "tactical"], mount="floor", tags=["bridge"], solid=True)
def console_station(m, i, label, rng):
    m.box((1.2, 0.9, 0.7), (0, 0.45, 0), "hull_dark", bevel=0.02)   # size, centre, material
    m.screen((0.5, 0.3), (0, 1.1, 0.2), "radar", rot=(-0.4, 0, 0), bezel=0.02)
```

* `family(category, labels, mount, tags, solid, mount_y)` registers one generator that is
  called once per label (`i` = index, `label` = the variant name, `rng` = `random.Random` seeded
  from the model id). Model id = `<category>_<label slug>`, file `models/<category>/<id>.glb`.
  **Every variant must look different** (different proportions / details / colours / parts),
  not just a recolour. Use `i`/`label`/`rng` to drive the differences.
* A module may define many families (functions) - the sum of all labels in the repo is
  exactly **1000**.

## Coordinates and units
Authoring frame = glTF/Godot frame: **+X right, +Y up, +Z front**. 1 unit = 1 metre; model at real
world scale. Origin by `mount`:

| mount   | origin                                         | notes |
|---------|------------------------------------------------|-------|
| floor   | bottom-centre of footprint, y=0 is the floor   | front faces +Z |
| wall    | centre of the back plane (z=0); extends to +Z  | `mount_y` = default height of the origin above the floor (default 1.5 m) |
| ceiling | centre of the top surface; extends downward (-Y) | |
| table   | bottom-centre of a small item                  | rests on a table/shelf/desk |

## Kit API (`Model` m)
`box(size, pos, mat, bevel=0, rot=(rx,ry,rz))`, `boxb(p0, p1, mat, bevel)`,
`cyl(r, h, pos, mat, axis='y'|'x'|'z', seg=16, r2=None, cap=True, rot, bevel)` (frustum with r2),
`sphere(r, pos, mat, seg, ring, scale)`, `torus(R, r, pos, mat, axis, seg, tseg, arc)`,
`prism(points2d, h, pos, mat, plane='xz'|'xy'|'zy')`, `quad(size, pos, mat, rot)`,
`screen(size, pos, tex, rot, bezel)` (emissive UI texture), `link(a, b, r, mat)` (rod between
two points), `tube(points, r, mat)`, `mirror_x()`, `group(name, pivot)` (start a separate named
mesh node, e.g. moving parts; `m.group("body")` returns to the main mesh).
`rot` is Euler XYZ radians in the game frame.

Materials (strings): hull_light hull_mid hull_dark steel brushed_alu chrome copper brass gold_trim
black_metal gunmetal rubber plastic_white plastic_black plastic_grey ceramic hazard_yellow
paint_red paint_orange paint_blue paint_teal paint_green paint_white paint_gold paint_grey
paint_navy fabric_navy fabric_grey fabric_red fabric_tan fabric_teal leather_black leather_brown
wood_dark wood_light foam cardboard leaf soil water food_red food_green food_brown concrete carbon
screen_off; emissive: em_white em_warm em_cyan em_blue em_amber em_red em_green em_violet
em_orange; transparent: glass glass_blue glass_dark glass_green glass_amber.
Add your own with `kit.register_material("mymod_name", "#rrggbb", metallic, roughness[, emission=, alpha=])`.
Screen textures for `screen(...)`: radar waveform graph text starmap schematic bars warp vitals
power nav alert tactical systems lifesigns comm medical periodic hazard diagnostic globe.

## Budget & quality
* Realistic proportions, chamfered edges (`bevel` 0.005-0.03 on visible edges only), panel
  seams, bolts/greebles, emissive accents, hazard stripes, labels via screens. Avoid a
  bare-primitive look; but stay economical: **typically 300-2500 triangles and well under 100 KB per GLB**
  (hard limit 400 KB, enforced by `tests/test_project.py`; bevel only large visible edges; use `seg` 12-24
  for cylinders, 6-10 for small ones).
* Origins follow the mount table above and are checked by `tests/test_blender_tools.py`: a floor model's lowest
  point is y = 0, a wall model starts at the wall plane (z >= 0), a ceiling model hangs down from its origin.
* No humanoid figures. Nothing floating: parts must connect / rest on each other.
* Moving parts (doors etc.) go in separate `group()`s with sensible pivots.
* Deterministic: only use `rng` (never `random` global / time).

## Testing your module
```bash
python3 blender/build_all.py --out /tmp/$NAME --only '^(cat1|cat2)_' --jobs 1     # export
GODOT=/tmp/godot.sh tools/preview/run.sh /tmp/$NAME.png /tmp/$NAME/models/cat1/*.glb  # contact sheet (view the PNG!)
```
Look at the contact sheet and iterate until every variant reads clearly as what it is.

The architectural assets (stair flight, guard, sign, hull fascia) are generated separately by
`blender/build_arch.py` (see `blender/ARCH.md`) and are not part of the 1000-model catalogue.
